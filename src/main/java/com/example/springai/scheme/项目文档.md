# 项目文档

## 1. 项目概述

本项目是一个基于 **Spring Boot + Spring AI** 实现的网页版 AI 对话助手系统。

系统支持用户注册登录、普通 AI 问答、SSE 流式问答、多轮上下文、会话历史管理、自动生成对话摘要，以及通过工具调用查询城市实时天气等功能。

项目整体定位是一个功能较完整的 AI 聊天 Demo 或基础应用，核心业务流程为：

```text
用户注册/登录
    ↓
创建或选择会话
    ↓
发送问题
    ↓
AI 模型生成回答
    ↓
流式返回并保存会话历史
    ↓
历史过长时自动生成摘要
```

## 2. 主要功能

### 2.1 用户注册、登录和登出

认证接口位于 `/api/auth`：

| 请求 | 接口 | 说明 |
|---|---|---|
| POST | `/api/auth/register` | 用户注册 |
| POST | `/api/auth/login` | 用户登录 |
| POST | `/api/auth/logout` | 用户登出 |
| GET | `/api/auth/current` | 查询当前登录用户 |

主要特点：

- 支持用户名、密码和手机号注册。
- 注册时使用 BCrypt 加密密码。
- 用户名不能重复。
- 登录时校验用户名、密码和用户状态。
- 登录成功后将当前用户保存到 HTTP Session。
- 项目当前采用 Session 认证方式，没有使用 JWT。

前端页面：

- `src/main/resources/static/login.html`：登录和注册页面。
- `src/main/resources/static/user-home.html`：用户主页。

### 2.2 AI 聊天

聊天接口位于 `/api/chat`：

| 请求 | 接口 | 说明 |
|---|---|---|
| POST | `/api/chat` | 普通问答，返回结构化响应 |
| GET | `/api/chat?message=...` | 普通问答，直接返回文本 |
| GET | `/api/chat/stream?message=...` | 无会话上下文的流式问答 |
| POST | `/api/chat/stream/context` | 绑定用户会话的流式多轮问答 |

普通聊天响应包含以下信息：

- AI 回复内容。
- 使用的模型名称。
- token 使用量字段。

流式接口使用 Reactor `Flux<String>` 和 Server-Sent Events（SSE）返回内容，前端可以在 AI 生成过程中实时显示回复。

### 2.3 多轮对话和会话历史

会话接口位于 `/api/conversation`：

| 请求 | 接口 | 说明 |
|---|---|---|
| GET | `/api/conversation/list` | 查询当前用户的会话列表 |
| GET | `/api/conversation/{sessionId}` | 查询指定会话详情 |
| DELETE | `/api/conversation/{sessionId}` | 删除指定会话 |

会话功能包括：

- 创建新会话。
- 会话与用户绑定。
- 查询当前用户的历史会话。
- 查看完整消息记录。
- 继续已有会话。
- 删除会话。
- 显示最后一条消息预览。
- 按最后活跃时间倒序排列会话。

如果访问的会话不存在，或者不属于当前用户，系统不会允许继续使用该会话，而是创建新的会话。

前端页面：

- `src/main/resources/static/index.html`：AI 聊天页面。
- `src/main/resources/static/conversation.html`：会话历史和详情页面。

### 2.4 Redis 会话存储

项目使用 Redis 保存聊天会话数据，主要 Key 结构如下：

```text
conversation:{sessionId}:messages
conversation:{sessionId}:meta
user:conversations:{userId}
```

其中：

- `messages`：使用 Redis List 保存用户和助手消息。
- `meta`：使用 Redis Hash 保存会话元数据。
- `user:conversations:{userId}`：使用 Redis Set 保存用户拥有的会话 ID。

会话元数据包括：

- 会话创建时间。
- 最后活跃时间。
- 消息总数。
- 所属用户 ID。
- 对话摘要。
- 摘要对应的消息数量。

会话相关数据默认设置为 **24 小时过期**。

### 2.5 对话上下文控制和自动摘要

系统设置最多保留最近 **10 轮对话**，即约 **20 条消息**作为直接上下文。

当历史消息较多时，系统会：

1. 读取完整历史消息。
2. 调用 AI 模型生成一段约 200 字以内的摘要。
3. 将摘要保存到 Redis 会话元数据中。
4. 后续请求使用摘要加最近消息构建新的上下文。

最终发送给 AI 模型的上下文大致为：

```text
系统提示词
+ 之前对话摘要（如果存在）
+ 最近的历史消息
+ 当前用户消息
```

这样可以避免会话不断增长导致上下文过长，同时尽量保留早期对话中的关键需求和结论。

### 2.6 天气查询工具

项目实现了 `WeatherTool`，用于调用和风天气 API 查询实时天气。

AI 可以通过函数调用自动使用 `getWeather` 工具。工具参数为城市中文名称，例如：

```text
北京
上海
广州
```

天气查询结果包含：

- 当前温度。
- 体感温度。
- 天气状况。
- 相对湿度。
- 风向和风力等级。
- 气压。
- 能见度。

典型处理流程为：

```text
用户询问天气
    ↓
模型判断是否需要调用 getWeather
    ↓
根据城市名称查询城市 ID
    ↓
调用实时天气接口
    ↓
将天气结果交给模型
    ↓
模型生成最终回答
```

### 2.7 Markdown 展示

项目包含 `MarkdownService`，用于将 Markdown 文本转换为 HTML。

消息对象支持保存：

- `content`：消息内容。
- `originalContent`：原始 Markdown 内容。

保存原始 Markdown 的主要目的是：

- 前端可以使用 `marked.js` 渲染消息。
- 后续继续对话时，可以使用原始 Markdown 作为 AI 上下文。
- 避免把已经转换的 HTML 直接发送给模型。

## 3. 系统结构

### 3.1 Controller 层

```text
controller
├── AuthController
├── ChatController
├── ConversationController
└── AiUserController
```

职责如下：

- `AuthController`：处理注册、登录、登出和当前用户查询。
- `ChatController`：处理普通聊天、流式聊天和带上下文的聊天。
- `ConversationController`：处理会话列表、会话详情和会话删除。
- `AiUserController`：提供用户的增删改查和分页查询接口。

### 3.2 Service 层

```text
service
├── ChatService
├── ConversationService
├── AiUserService
├── MarkdownService
└── impl
    └── AiUserServiceImpl
```

职责如下：

- `ChatService`：封装 AI 模型调用、流式输出、工具调用和摘要生成。
- `ConversationService`：封装 Redis 会话、消息、元数据和摘要操作。
- `AiUserService`：定义用户业务接口。
- `AiUserServiceImpl`：实现用户注册、登录和密码校验。
- `MarkdownService`：提供 Markdown 转 HTML 功能。

### 3.3 数据访问层

```text
entity
└── AiUser

mapper
└── AiUserMapper
```

`AiUser` 对应关系型数据库中的 `AI_USER` 表，`AiUserMapper` 继承 MyBatis-Plus 的 `BaseMapper`，提供用户基础 CRUD 能力。

### 3.4 工具层

```text
utils
└── WeatherTool
```

`WeatherTool` 对接和风天气接口，并作为 AI 可调用的工具注册到聊天服务中。

## 4. AI 模型调用方式

项目使用两种 AI 调用方式：

### 4.1 Spring AI ChatClient

普通聊天和对话摘要使用 Spring AI 的 `ChatClient` 调用模型。

### 4.2 自定义 WebClient

流式聊天使用自定义 `WebClient` 调用 OpenAI 兼容接口：

```text
/v1/chat/completions
```

请求中包含：

- 模型名称。
- 是否流式输出。
- temperature。
- max_tokens。
- messages。
- 工具定义（如果需要工具调用）。

自定义 WebClient 的主要作用是适配当前 AI 服务的流式响应格式和工具调用流程。

流式返回内容会解析 `choices` 中的增量内容，并转换为 SSE 数据发送给前端。

## 5. 数据存储

### 5.1 关系型数据库

关系型数据库主要用于保存用户信息，对应表为：

```text
AI_USER
```

主要字段包括：

- `id`：用户主键。
- `user_bh`：用户编号。
- `user_name`：用户名。
- `password`：加密后的密码。
- `phone`：手机号。
- `status`：用户状态。
- `create_time`：创建时间。
- `update_time`：更新时间。

主配置中配置了 MySQL 数据源；测试配置中包含 PostgreSQL 数据源，用于连接测试。

### 5.2 Redis

Redis 主要用于保存：

- 会话消息。
- 会话元数据。
- 用户和会话的关联关系。
- 对话摘要。

项目中的测试代码包含 Redis 存取和删除验证，以及数据库连接、版本查询和表查询测试。

```text
src/main/resources/static/login.html
src/main/resources/static/user-home.html
```

## 7. 典型业务流程

### 7.1 用户登录流程

```text
用户填写用户名和密码
    ↓
调用 /api/auth/login
    ↓
后端查询 AI_USER 表
    ↓
BCrypt 校验密码
    ↓
用户信息写入 HTTP Session
    ↓
前端进入用户主页或聊天页面
```

### 7.2 带上下文的聊天流程

```text
用户发送消息
    ↓
检查登录状态
    ↓
校验 sessionId 是否属于当前用户
    ↓
没有有效会话时创建新会话
    ↓
将用户消息写入 Redis
    ↓
读取摘要和最近历史消息
    ↓
判断是否需要生成新的摘要
    ↓
调用 AI 模型
    ↓
通过 SSE 流式返回 Markdown 内容
    ↓
AI 回复完成后保存到 Redis
    ↓
返回会话 ID
```

### 7.3 天气工具调用流程

```text
用户询问某城市天气
    ↓
模型请求调用 getWeather
    ↓
系统执行 WeatherTool
    ↓
查询城市 ID
    ↓
请求和风天气实时天气接口
    ↓
将工具结果添加到模型上下文
    ↓
模型生成最终自然语言回答
```

## 8. 项目特点总结

项目目前具备以下特点：

- 具备完整的登录注册和会话认证流程。
- 支持普通问答和 SSE 流式问答。
- 支持用户级别的会话隔离。
- 使用 Redis 保存多轮对话历史。
- 支持历史消息数量控制和自动摘要。
- 支持 Markdown 格式的 AI 回复。
- 支持 AI 工具调用和实时天气查询。
- 使用 MyBatis-Plus 管理用户数据。
- 同时包含数据库和 Redis 的基础连接测试。
- 前端采用简单直观的原生 HTML 页面，便于部署和演示。

总体来看，本项目是一个面向 AI 对话场景的基础应用框架，可以继续扩展知识库问答、文件上传、权限管理、消息搜索、更多 AI 工具以及管理后台等功能。
